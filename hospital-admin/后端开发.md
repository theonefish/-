一、后端技术架构
该项目后端采用 Spring Boot 生态进行开发，整合了以下核心技术组件：
1. 权限安全框架：Spring Security + JWT，实现用户身份认证、权限控制，同时支持 Redis+Token 的登录状态管理（加分项设计）
2. ORM 框架：MyBatis-Plus，简化数据库操作，提供分页、条件构造等能力
3. 数据加密：MD5 密码加密，保障用户账号安全
4. 事务管理：Spring 声明式事务，保障核心业务的数据一致性
5. 接口规范：RESTful 风格接口，统一返回结果封装（ResultVo）
二、用户端后端核心接口实现
1. 用户注册登录接口
- 注册接口：/add（POST）
  - 功能：校验账号唯一性，对用户密码进行 MD5 加密后存入数据库，初始化用户账号状态
  - 关键逻辑：查询数据库判断账号是否已被占用，若未占用则加密密码并完成用户数据入库
- 登录相关：支持微信一键登录（80 分项目），配合 Redis 存储登录令牌，提升登录态管理效率
2. 意见反馈接口
- 反馈提交接口：/addSuggest（POST）
  - 功能：接收用户提交的反馈信息，自动填充创建时间，完成反馈数据入库
3. 预约挂号核心接口
- 预约下单接口：/makeOrderAdd（POST）
  - 功能：核心挂号业务，先校验剩余号源，若有剩余则创建预约订单，同时扣减对应排班的剩余号数
  - 事务保障：使用@Transactional注解，保证订单创建和号源扣减两个操作的原子性，避免超卖
- 检查报告查询接口：/getProberepOrderList（GET）
  - 功能：多表关联查询用户的检查报告信息，关联就诊人、医生、科室信息，按创建时间倒序返回分页数据
  - 关联逻辑：通过 MPJLambdaWrapper 实现多表左连接查询，同时根据当前用户 ID 过滤数据，保障数据权限
4. 就诊人管理接口
- 支持就诊人的新增、修改、删除，接口会自动获取当前登录用户的 ID，将就诊人与用户进行绑定，保障数据隔离
三、管理端后端核心接口实现
1. 后台登录接口
- 登录接口：/login（POST）
  - 功能：
    1. 验证码校验：校验前端输入的验证码与 Session 中存储的验证码是否一致
    2. 身份认证：通过 Spring Security 完成用户名密码的认证
    3. 令牌生成：认证通过后生成 JWT 令牌，同时返回用户 ID、昵称、身份类型（管理员 / 医生）
  - 权限区分：根据用户是否为超级管理员，返回不同的身份标识，用于前端界面权限控制
2. 系统管理模块接口
角色管理
- 角色列表查询接口：/getList（GET）
  - 功能：分页查询角色列表，支持角色名称模糊搜索，按创建时间倒序排序
  - 同时支持角色菜单分配，实现不同角色的权限隔离
菜单管理
- 上级菜单查询接口：/getParent（GET）
  - 功能：查询所有顶级菜单，用于新增 / 编辑菜单时的上级菜单选择
3. 门诊管理模块接口
医生管理
- 密码重置接口：/resetPassword（POST）
  - 功能：管理员可重置医生的登录密码，默认重置为666666，重置前会对密码进行加密
  - 权限控制：通过@PreAuthorize("hasAuthority('sys:user:reset')")实现接口级别的权限控制，仅拥有对应权限的管理员可调用
排班管理
- 批量删除接口：/delList（POST）
  - 功能：支持批量删除排班数据，提升管理员操作效率
  - 权限控制：接口级权限校验，保障操作安全性
预约管理
- 叫号接口：/callVisit（POST）
  - 功能：将预约信息流转到就诊管理模块，完成叫号流程的状态流转
就诊管理
- 医嘱编辑接口：/edit（PUT）
  - 功能：医生 / 管理员填写医嘱，同时更新预约的就诊状态，标记该预约已完成就诊
  - 事务保障：使用@Transactional保证医嘱入库和预约状态更新的原子性
  - 权限控制：接口级权限校验，仅拥有对应权限的人员可操作
四、后端关键机制
1. 权限控制体系
- 实现了 RBAC（基于角色的访问控制）权限模型，通过角色 - 菜单的多对多关系，实现不同角色的菜单权限控制
- 接口级权限控制：通过@PreAuthorize注解，对敏感接口进行权限校验，保障系统安全
- 数据权限控制：用户只能查看自己相关的预约、报告等数据，管理员可查看全量数据
2. 数据安全机制
- 密码加密：用户密码均通过 MD5 进行加密存储，避免明文密码泄露
- 验证码机制：后台登录加入验证码，防止暴力破解
- 数据隔离：通过用户 ID 进行数据隔离，不同用户无法查看他人的就诊、预约信息
3. 业务一致性保障
- 核心业务（挂号、就诊）使用声明式事务，保证多步数据库操作的原子性，避免数据不一致
- 号源并发控制：挂号时先校验剩余号源，再进行扣减，避免超卖问题
